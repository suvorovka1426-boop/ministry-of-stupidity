# Министерство глупостей — V19 · страны, монеты, скины, ЮMoney

## Быстрый запуск (Windows)
1. Распакуйте архив и откройте папку `ministry-of-stupidity` (именно ту, где лежит `server.py`).
2. В адресной строке Проводника введите `powershell` и нажмите Enter.
3. Запустите `python server.py`.
4. Откройте `http://127.0.0.1:8765`.
5. При наличии Shupp ключа задайте `$env:SHUPP_API_KEY = Read-Host 'Shupp API key'` и `$env:SHUPP_MODEL = 'shugg'` **до** запуска Python.

Не закрывайте окно PowerShell, пока игра нужна. Для корректной работы API не открывайте `index.html` напрямую (`file://`).

## Новая игровая экономика (V19)
- Бесплатные страны: **Россия, США, Китай**. Клик по карточке сразу начинает партию.
- Открываемые страны: **Япония 75**, **Израиль 90**, **Италия 105**, **КНДР 120** игровых монет. Если средств хватает, клик по карточке покупает страну и сразу начинает игру. Если не хватает, открывается казна с возможностью вернуться к бесплатной стране.
- За выбор «Принять» выдаётся 7 монет, «Отклонить» — 6 монет. За завершение 20 дней начисляется ещё 30.
- Общие монеты не конвертируются по валютному курсу: цены на страны, темы и скины указаны в 🪙. Настоящие валюты остаются в информационных API и контексте стран.
- Скины: Классика (бесплатно), Агент бюрократии (35), Киберминистр (60), Король указов (90), Космический чиновник (115). Визуальные эффекты — портрет и рамки; игровой баланс не меняется.
- Сохранение бесплатного прогресса и unlock-ов в `localStorage`; как и в V18, это локальная браузерная игра, не синхронизированная между устройствами.

## Добровольный донат ЮMoney (реальные деньги)
- **10 ₽ → 120 🪙**. Это установленная нами небольшая цена набора, не утверждение о юридическом/техническом минимуме самого ЮMoney.
- Кнопка открывается по нажатию на 🪙 в игровом заголовке или через «＋ Монеты и донат» на экране выбора стран.
- Сервер создаёт заказ в SQLite, отправляет игрока на официальную форму ЮMoney, ждёт HTTP-уведомление с HMAC-SHA256 `sign`. Только серверно подтверждённый перевод меняет статус `pending` на `paid`.
- После подтверждения нажмите «Проверить покупки» и «Зачислить +120 🪙». Набор списывается один раз, 120 монет зачисляются в серверный кошелёк. Платная часть баланса хранится в SQLite; при трате платных монет на предмет сервер списывает их и сохраняет право владения предметом.
- В тестах используются **искусственные уведомления с тестовым секретом**, реальные переводы не выполнялись.
- **Реальные платежи выключены по умолчанию**. Для включения нужны публичный HTTPS URL, защищённая и постоянная SQLite или другая БД, настроенный вебхук `https://YOUR_DOMAIN/api/payments/webhook`, проверка соответствия законам и правилам ЮMoney, а также резервное копирование/восстановление покупок. `YOOMONEY_ENABLE_LIVE=YES` и `PAYMENTS_PERSISTENCE_CONFIRMED=YES` не устанавливайте до выполнения этих пунктов.

### Переменные окружения при реальном размещении

```powershell
$env:SHUPP_API_KEY = Read-Host "Shupp API key"
$env:SHUPP_MODEL = "shugg"
$env:YOOMONEY_WALLET = Read-Host "YooMoney wallet number"
$env:YOOMONEY_NOTIFICATION_SECRET = Read-Host "YooMoney notification secret"
$env:YOOMONEY_ENABLE_LIVE = "NO"
$env:PAYMENTS_PERSISTENCE_CONFIRMED = "NO"
python server.py
```

Не загружайте `.env`, API-ключи, секреты, базу данных или записи покупок в GitHub. Полный пример параметров — `.env.example`.

**Ограничения перед коммерческой публикацией:** заработанные офлайн-монеты контролируются браузером и могут быть изменены пользователем; для полноценной экономики с реальными продажами нужно перенести и бесплатные игровые начисления на сервер. Кроме того, восстановление платного кошелька сейчас основано на токене в браузере: для массового запуска нужны аккаунты/механизм восстановления и резервное копирование базы. Личные P2P-переводы за цифровые товары могут не соответствовать условиям ЮMoney и законодательству. До выполнения этих пунктов не принимайте реальные платежи.

## Проверка
В папке запуска:

```powershell
python -m unittest test_release.py test_economy.py -v
```

Тесты не отправляют деньги и не обращаются к платёжному сервису. Они проверяют логику подписанных *синтетических* уведомлений, запрет повтора и списание за предметы.

- Игровые API: Open-Meteo (погода), World Bank (экономика), Shupp (ИИ-законы); REST Countries с резервом World Bank.

- **Два настоящих платежа, если они необходимы по ТЗ, ещё не совершались и не считаются выполненными.** Нельзя выполнять их до соблюдения правил сервиса и стабильного хранилища.

## V21: усиленное влияние внешних API

Во вкладке «Игра» появилась панель «Ситуация в стране». Теперь реальные показатели
влияют на каждое решение и ежедневные расходы; эффект показан заранее в прогнозе для
кнопок «Принять» и «Отклонить».

* REST Countries / World Bank population: численность населения масштабирует затраты закона и дополнительные расходы.
* Open-Meteo: осадки, жара или мороз вводят видимые ежедневные последствия для бюджета, счастья и порядка.
* World Bank: инфляция усиливает расходы и стоимость затратных указов; при отсутствии данных штрафа нет.
* Currency API: текущий курс относительно фиксированного **игрового ориентира** может изменить ежедневный бюджет (это не реальная финансовая модель).
* Shupp AI: по кнопке придумывает тематический закон с учётом температуры, осадков, населения, инфляции, дня и состояния страны.

Все штрафы и множители игровая условность, а не точные экономические прогнозы. Если источники недоступны, модификаторы по ним равны нулю. Ключи по-прежнему остаются на Python-сервере. Платёжная логика и цены не менялись.


## V22 · 🏆 Таблица лидеров

- Работает **сразу локально**, без ключей: лучшие результаты каждого ника для каждой страны сохраняются в `ministry_scores.sqlite3` на Python-сервере.
- Вкладка «Лидеры»: фильтр по стране, первые 20 игроков, медали, подсветка своего ника и кнопка отправки результата после окончания партии (даже проигранной).
- API: `GET /api/leaderboard?country=ALL` или `?country=RU`, `POST /api/leaderboard`. Публикация требует подтверждённого завершения партии на стороне клиента; сервер проверяет формат данных и частоту отправки, но это пока **не античит**. Не используйте рейтинг с призами.
- Для **общего онлайн-рейтинга** установи переменные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` только на сервере и выполни `supabase.sql` в Supabase. В HTML ключей нет.
- На бесплатном Render локальный SQLite без persistent disk может потеряться после перезапуска или деплоя. Для постоянного публичного рейтинга обязательно подключить Supabase.
- Локальные рекорды не переносятся автоматически в Supabase.


## V23 — подключение настоящего Supabase

1. Создай проект: https://supabase.com/dashboard > New project. Дождись, пока база будет готова.
2. В проекте открой **SQL Editor** > New query. Вставь **весь** `supabase.sql` из V23 и нажми Run. Скрипт совместим со старой таблицей из V22; при первом запуске SQL удаляет дубликаты менее удачных результатов.
3. В **Project Settings > API Keys** найди `Secret key` формата `sb_secret_...` (рекомендуется). **Project URL** формата `https://...supabase.co` копируется в Connect или в настройках API.
4. В PowerShell в папке с `server.py` выполни:

```powershell
$env:SUPABASE_URL = Read-Host "Supabase Project URL"
$env:SUPABASE_SECRET_KEY = Read-Host "Supabase server secret key"
python server.py
```

Старый ключ `service_role` по-прежнему работает, но его нужно вводить через `$env:SUPABASE_SERVICE_ROLE_KEY`, а не через `SUPABASE_SECRET_KEY`.

5. Открой http://127.0.0.1:8765 > Играть > страна > Лидеры > **Проверить Supabase**. Должно написать, что общая база подключена. Прямую проверку также можно сделать через `http://127.0.0.1:8765/api/leaderboard/check`.
6. На Render добавь **только в Environment** `SUPABASE_URL` и `SUPABASE_SECRET_KEY`. Ни одна секретная переменная не должна быть в `index.html`, `render.yaml` или GitHub.

**Общее облачное хранилище:** при включённом Supabase локальный рейтинг SQLite перестаёт использоваться. В базе хранится лучший результат каждого ника в каждой стране благодаря атомарной PostgreSQL-функции. Старые локальные рекорды автоматически не мигрируют.

**Ограничения:** счёт и завершение партии пока сообщаются браузером. Это не защищённый от читов соревновательный рейтинг и не подходит для розыгрышей денежных призов. Для публичного античита нужен серверный расчёт законов и очков, а также аккаунты. Настройка Supabase не включает реальные переводы ЮMoney; они остаются выключены.


## V24: подготовка настоящих донатов на публичном сайте

В составе готовая форма ЮMoney: покупатель нажимает «Оплатить 10 ₽», попадает на официальный сайт ЮMoney, после завершения возвращается в игру. Возврат на сайт **не означает оплату**. Только HTTP-уведомление `POST /api/payments/webhook`, проверенное сервером через HMAC-SHA256, меняет статус заказа на `paid`. После получения оплаты игрок нажимает «Проверить покупки» и «Зачислить +120 🪙». Платёж и выдача монет записываются на сервере, двойная выдача запрещена.

### Для Render / реальных платежей

**Render с постоянным диском платный**. `render.yaml` теперь использует план `starter` и постоянный диск `/var/data`; подтвердите цену в кабинете Render перед публикацией. На бесплатной версии с временной файловой системой **не включайте** приём настоящих денег.

1. Создайте GitHub-репозиторий из файлов игры, не загружая секреты, `.env`, базы данных.
2. Разверните `render.yaml` через Render Blueprint и дождитесь стабильной HTTPS-ссылки.
3. В разделе Environment укажите `PUBLIC_BASE_URL=https://ваша-игра.onrender.com`, `YOOMONEY_WALLET`, `YOOMONEY_NOTIFICATION_SECRET`, `PAYMENTS_DB_PATH=/var/data/ministry_payments.sqlite3`.
4. В ЮMoney включите HTTP-уведомления на `https://ваша-игра.onrender.com/api/payments/webhook` (только один адрес на один кошелёк). Проверяйте через кнопку тестового уведомления в ЮMoney: тест **не** должен начислять монеты.
5. Проверьте соблюдение требований ЮMoney и законодательства для приёма оплаты цифровых товаров (личный кошелёк может оказаться неподходящим). Обеспечьте резервное копирование базы и восстановление токенов покупателей.
6. Лишь после выполнения проверок установите `PAYMENTS_PERSISTENCE_CONFIRMED=YES` и `YOOMONEY_ENABLE_LIVE=YES`.
7. Проведите контролируемую настоящую покупку 10 ₽ и проверьте запись `paid`, зачисление 120 монет **ровно один раз**, сохранность баланса после перезапуска.

Данные проекта не публикуются в клиентском HTML. **Не обещайте игрокам приём платежей, пока пункты 1–7 не выполнены.**

Официальная документация: https://yoomoney.ru/docs/payment-buttons/using-api/forms и https://yoomoney.ru/docs/payment-buttons/using-api/notifications
